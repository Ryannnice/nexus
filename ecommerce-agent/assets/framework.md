  ## 1. 从视频中采用了什么

  保留了视频的核心思想：

  - 由 Context Orchestrator 管理有限上下文，而不是把全部历史塞给模型。
  - 区分近期历史、滚动摘要、长期记忆和结构化状态。
  - 使用滑动窗口，旧事件边运行边压缩。
  - 只在存在指代、继承、取消、修正或远期引用时读取历史。
  - 为 Token、超时、召回失败和非法模型输出设计明确降级路径。
  - 用结构化状态作为稳定锚点，避免历史内容漂移。

  没有直接采用：

  - 视频的固定 8K Token 分配方案；
  - 完整 user/assistant 对话拼接；
  - LLM 自由生成递归摘要；
  - 所有历史统一进入向量库；
  - 通用用户画像、情感和闲聊记忆；
  - 工具执行结果记忆——当前项目没有真实工具执行器。

  ## 2. 针对算法项目做的适配

  本项目只预测有序工具 ID，不生成聊天回复，因此我将通用对话记忆改造成“工具规划记忆”：

  当前 query
    → Context Router
    → 读取必要的近期状态/长期证据
    → 确定性生成短 resolved_query
    → 原 0.6B Intent
    → 原 canonical Top-10
    → 原 8B DPO Planner
    → 有序工具 ID

  关键调整：

  - Planner 不接收历史原文、摘要或历史候选，只接收短 resolved_query。
  - Planner Prompt、候选 Top-10、模型权重和 greedy 解码保持不变。
  - 摘要由确定性 reducer 生成，每个目标保留来源 turn。
  - 长期记忆采用会话内精确 turn + BM25，没有复用工具 Embedding。
  - 历史 Planner 预测只能记为 planned_tools，不能反向变成用户目标。
  - 无可靠来源的纯引用直接安全空返回，不猜测历史。
  - SQLite 提供会话隔离、版本冲突检测、30 天 TTL 和整会话删除。

  - N=2/3/4：E 架构质量相同，选择最小窗口 2。

  E-n2-k2-t640

  - 长期记忆超时：安全空返回并记录告警。
