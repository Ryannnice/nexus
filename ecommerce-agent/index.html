项目概览

一条连续的三阶段实验路线

本项目围绕同一份 100 工具目录构建一条连续系统链路：先判断请求是否进入工具系统；再由 BM25、任务内微调向量模型、任务内重排模型与 RRF 生成高覆盖候选集；最后由 Qwen3-4B/8B 从候选视图或完整目录中输出有序工具 ID。

当前最终系统结果 静态全链路成功率 · 90.37%

工具链规划采用 Qwen3-8B 混合表达监督微调模型（版本 2429），全链路统计固定使用 Qwen3-1.7B 路由预测。在静态全链路测试集（3,000 条闲聊 + 6,000 条电商）上，工具链口径成功 8,133 / 9,000（90.37%），集合口径成功 8,153 / 9,000（90.59%）。接口式表达测试集（1,000 条）的 99.70% 只说明规划模块本身；候选顺序稳健模型仅用于候选排列可能变化的场景。

三个模块的指标分类准确率 → 完整召回率 → 集合 / 工具链全对率

路由、检索和规划使用不同输出与计分协议；部分测试共享同一批基础请求，但模块指标仍不能直接相乘。最终结果在 9,000 条静态全链路测试中逐样本联合统计，并固定使用 1.7B 路由预测；0.6B 的 100% 是单独的模块选择结果。

系统设计 · 四项关键决定

01

按请求类型智能分流

入口模型区分电商诉求与开放闲聊，把计算集中在真正需要工具的请求上。

02

以完整集合覆盖为目标

候选检索测试中的单工具与最多六工具请求采用统一口径，确保任务链所需能力全部进入候选。

03

分层提升候选质量

先用混合检索建立高覆盖候选，再以任务内重排模型补充请求与工具之间的交互判断。

04

从候选集合生成有序轨迹

Qwen3-4B/8B 从 Top-10 候选或完整 100 工具目录中选择精确工具集合，并按照用户要求与依赖关系排序。
