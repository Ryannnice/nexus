01 · PROJECT CHALLENGE

从一句复合诉求，
到一组可执行工具。

真实电商请求常把订单、物流、优惠与售后组合在同一句话中。项目的目标不是只识别一个最相关工具，而是为后续 Agent 执行完整找回每一项必要能力。

PARTIAL HITFAIL

“查一下订单详情、物流状态，并帮我确认退款进度。”

GOLD SET order_detaillogisticsrefund_status
TOP-K COVERS order_detaillogisticsrefund_status · MISSING

命中 2/3，但执行链仍不完整。

COMPLETE HITPASS

同一个请求，Top-K 覆盖全部三个必要工具。

GOLD SET order_detaillogisticsrefund_status
TOP-K COVERS order_detaillogisticsrefund_status

Gold ⊆ Top-K，才记为一次成功。

PRIMARY METRIC

AllHit@K

若当前 Query 的全部 Gold Tools 都在 Top-K 中，则为 1；否则为 0。

Gold ⊆ Top-K→ 1
Gold ⊄ Top-K→ 0
K=10 衡量短名单质量；K=30/50 衡量候选覆盖。
01

按请求类型智能分流

入口 Intent Gate 区分电商诉求与开放闲聊，把计算集中在真正需要工具的请求上。

02

以完整集合覆盖为目标

单工具与最多六工具请求采用统一口径，确保任务链所需能力全部进入候选。

03

分阶段提升候选质量

先用混合检索建立高覆盖候选，再以任务内 Reranker 补充 Query–Tool 交互判断。

06 · SYSTEM INSIGHT

稳定召回与交互判断，
共同决定最终排序。

任务内训练让一阶段 Source 准确学习工具边界，Reranker 则补充 Query–Tool 的细粒度交互。实验表明，两路排序经过 RRF 融合后形成更强互补，AllHit@10 从 Source 的 95.95% 提升到 98.30%。

01 · REPRESENTATION

任务内表示学习贡献主要增益

bge-large 从 Zero-shot 47.63% 提升至微调后的 95.75%，说明能力边界学习是检索质量的核心。

02 · COMPLEMENTARITY

两种排序信号各有优势

Source 保持全局候选稳定性，Task Reranker 强化候选对之间的细粒度语义比较。
