01 · PROBLEM DEFINITION

多意图任务里，
“命中一个”远远不够。

用户可能在一句话里同时请求订单详情、物流、退款和售后。如果只找回其中一部分，Agent 仍无法完整执行任务。因此项目采用严格的工具集合覆盖指标，而不是只看第一个工具是否命中。

PARTIAL HITFAIL

“查一下订单详情、物流状态，并帮我确认退款进度。”

GOLD SET order_detaillogisticsrefund_status
TOP-K COVERS order_detaillogisticsrefund_status · MISSING

命中 2/3，但执行链仍不完整。

COMPLETE HITPASS

同一个请求，Top-K 覆盖全部三个必要工具。

GOLD SET order_detaillogisticsrefund_status
TOP-K COVERS order_detaillogisticsrefund_status

Gold ⊆ Top-K，才记为一次成功。

PRIMARY METRIC

AllHit@K

若当前 Query 的全部 Gold Tools 都在 Top-K 中，则为 1；否则为 0。

Gold ⊆ Top-K→ 1
Gold ⊄ Top-K→ 0
K=10 衡量短名单质量；K=30/50 衡量候选覆盖。

06 · KEY FINDING

强 Retriever 之后，
不要让 Reranker 直接接管。

任务内训练让一阶段 Source 已经非常强。通用 Reranker 直接覆盖排序时，AllHit@10 从 95.95% 跌到 70.28%；即使任务内微调，纯重排仍略低于 Source。最终方案把 Reranker 当作 residual 信号。

08 · LIMITS & NEXT

结果有效，
但边界必须写在同一页。

页面将项目定位为可复现的工具选择实验，不把闭集指标包装成生产级 Agent 能力。下面四条限制决定了哪些结论可以说、哪些还不能说。

01

已知工具闭集

Train/Test 使用相同的 100 个工具全集，没有验证新增工具、长尾工具或开放目录检索。

02

合成表达分布

数据完成表达簇隔离和审计，但语言仍主要来自合成模板，不等同于真实用户请求。

03

模块级评测

Intent 与工具检索分别评测；尚未测量工具真实调用、参数正确性、任务完成率和业务结果。

04

模型选择治理

多个 Embedding Run 曾在同一 Test 上横向比较，后续需要全新且从未触碰的 Final Holdout。
