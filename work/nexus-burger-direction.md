# NEXUS Burger 网站设计方向

状态：讨论稿。记录已确认的叙事方向，并细化后续原型；不是已完成的网站或已选定的模型。

## 已确认的方向

- 保留现有主站、电商 Agent 页面及资源文件。新版在独立开发目录和分支中制作，先独立预览。
- NEXUS 是组织名称；汉堡王是成员之间的昵称，也是这次设计的主题来源。
- 主线采用：完整汉堡开场 → 食材展开 → 认识技术方向与学习资料 → 汉堡合拢 → 镜头拉远，揭示成员圆桌。
- 不采用圆桌先出现的开场方案。
- 滚动推动主要叙事。点击用于查看完整资料或具体成员信息，主线不依赖连续点击才能继续。
- 真实的食材质感与连贯转场是视觉原型的首要目标。
- 之前的 nexus-burger-concept.html 是交互结构示意，简化图形不代表正式食材质量。

## 视觉语言

画面采用奶油色背景、烘烤棕文字、红色行动按钮，以及食材本身的自然颜色。标题圆润厚实，中文长文保持清晰易读。

品牌主体写 NEXUS；可将 THE BURGER CLUB 作为暂定的次级字样。导航暂定为「我们的配方」「学习菜单」「同桌伙伴」「加入 NEXUS」。

食物呈现广告摄影式的真实感。桌子、餐具与人物采用温暖、简洁的造型，保持一致的灯光和色调。

参考汉堡王的布局和视觉语言，按 NEXUS 的内容与组件结构重新实现。暂不沿用旧站的绿色科技风设计规范。

## 连续分镜

以下比例只用于讨论叙事篇幅，最终以真实模型、文字量和设备测试调整。不是滚轮事件次数，也不是自动播放时长。

### 01 / 完整汉堡：建立第一印象

参考篇幅：主线的前 12%。

汉堡是第一眼的主体，采用略微俯视的三分之四角度。首屏只呈现 NEXUS、一句组织介绍，以及向下探索的提示。

材质和构图优先体现面包体积、肉饼厚度和菜叶边缘。背景保留充足空间。已有内容先出现，食材资源完成加载后平稳进入画面。

可尝试的文案方向：

- 好东西，层出不穷。
- 把不同的想法，放到一起。

上面两句是候选文案，不同时作为首屏主标题。

### 02 / 展开：从食物读出组织结构

参考篇幅：12%–30%。

上层面包先升起，其他食材沿纵向错时展开，并有少量侧向位移和旋转。食材保持明显的上下关系。

镜头拉远和分层同时发生，避免食材冲出画面。每层在空间稳定后显露对应标签。

回弹幅度保持克制：面包有重量，肉饼更稳，菜叶和芝士有更柔软的运动。

滚动停下，主动画停在当前构图；向上滚动能够准确还原。

### 03 / 技术方向：让观看与阅读交替发生

参考篇幅：30%–70%，是主线篇幅最多的部分。

滚动在各方向之间推进。到达一个方向时，镜头靠近对应食材，其他食材仍留在空间中，保持位置关系。

每个方向都有稳定的阅读段：方向名称、一句话说明、少量精选资料。阅读段内降低镜头位移；继续滚动，再进入下一层。

方向之间的镜头运动采用一致的路径逻辑，以轻微平移、上下移动和推进为主。每一层的细节变化由食材材质和柔软程度表现。

完整资料由显式的「学习菜单」入口打开。选择食材和选择对应文字入口得到相同结果。

### 04 / 合拢：把方向重新组成 NEXUS

参考篇幅：70%–85%。

文字先有序退场，食材依次归位；最后上层面包落下，完成轻微的压合与回弹。

合拢有明确的顺序和重量变化。保持模型、灯光和视角连续，给完整汉堡一个短暂的展示位置。

文案可尝试：「不同方向，同一张桌。」

### 05 / 入席：揭示一起做事的人

参考篇幅：85%–100%。

同一个汉堡落在桌面中央。镜头连续后退，原先只看见的一小块桌面逐渐显露为完整圆桌，周围的人物与院校桌牌进入画面。

最初出现的是桌面轮廓和少量前景人物；随后显示其他座位，避免人物同时弹出的突兀感。

学校信息代表成员来源。每个院校或校区条目对应一个代表人物和人数标记，数量更多的学校不堆叠大量相同人物。

结束位置留一张空椅或一个空餐位，对应「加入 NEXUS」。加入渠道需要沿用真实有效的联系方式，当前不虚构表单或邀请地址。

## 食材与内容的暂定对应

| 食材 | 内容 | 视觉重点 |
| --- | --- | --- |
| 上层面包 | NEXUS 的组织介绍与共同愿景 | 烘烤色差、芝麻、孔隙与体积 |
| 生菜 | 具身智能 | 薄边透光、叶脉、自然褶皱 |
| 煎蛋 | 推荐系统 | 蛋白与蛋黄的材质差异、柔和高光 |
| 芝士 | Agent | 柔软下垂、边缘弯曲和轻微拉伸 |
| 肉饼 | LLM 后训练 | 焦化纹理、不规则边缘和局部油光 |
| 底层面包 | 基础知识与 AI Infra | 可靠的底座、烤痕与面包内部组织 |

对应关系是内容组织的提案，可替换食材或调整顺序。基础知识与 AI Infra 共享一个食材入口，资料分类仍分别保留。

## 学习菜单

当前数据：107 项资料，分为基础知识 16、Infra 26、Agent 23、具身智能 18、后训练 16、推荐算法 8。

- 画面上的短标签只承担定位，不承载整段文章。
- 未打开菜单时，主线可通过滚动完整浏览。
- 桌面端完整资料用右侧菜单承接；移动端用更适合阅读的独立内容面板。
- 打开菜单时保存当前章节、滚动位置与相机状态，暂停场景推进。
- 菜单内的阅读动作不推动背景汉堡；关闭后恢复原位置。
- 资料链接保留标题、来源、原地址。菜单外观可参考纸质餐单，信息结构沿用真实学习资料。
- 顶部导航提供直接访问学习菜单的入口，回访者可以跳过主线动画。
- 桌面键盘、手机触摸都能使用；内容不依赖悬停才可发现。

## 成员圆桌

当前 HTML 中有 23 个院校或校区条目，旧页面文案仍写 22。后续页面数量从同一份数据生成。

人物共享一套基础造型，可用校徽主色调整衣服、围巾或帽子。校徽放在桌牌或胸牌，校名与人数在清晰的平面信息区呈现。

人物动作以轻微招手、转头、入席为主。食材模型与主转场完成之前，不优先制作复杂进食动作。

主线镜头提供圆桌整体印象。完整院校名册可直接阅读；点击某个院校时，再用短距离镜头调整突出对应座位。

构图应给校徽留出独立位置，避免远处人物、后排桌牌和中央汉堡互相遮挡。移动端以少量前景人物和清晰名册保留信息。

## 动画与阅读规则

- 运动段与阅读段交替，给每个方向留出稳定构图。
- 保留原生页面滚动的预期；不把一次滚轮输入强制锁成一整段长动画。
- 快速跳过、缓慢滚动、反向滚动都能到达正确画面。
- 导航跳转到章节时直接同步场景进度。
- 正文始终是正常 HTML，保持选中、复制、链接与键盘访问。
- 减少动态效果偏好下，提供静态分层图和完整内容。
- 手机保留主线顺序，缩短镜头位移，并按设备能力调整渲染质量。

## 正式模型的验收条件

食材应能独立控制，名称、层级和旋转中心清晰。合拢与展开都能成立，打开后的上下表面、侧面和内部不能缺失。

重点检查：

1. 首屏距离下，食材比例、轮廓、接触关系是否自然。
2. 特写距离下，面包、肉饼、菜叶是否仍有足够细节。
3. 灯光变化和镜头移动时，高光与阴影是否一致。
4. 芝士和菜叶的轻微形变是否出现破面或穿插。
5. 上传到网页的贴图、模型与材质是否适合实时渲染。

已检查 Burger House 3D 中两个汉堡 GLB：都只有一个网格，没有现成食材节点。可以参考加载方式，拆分适用性需要进一步检查。

现成资产如果无法满足分层与特写需求，应在建模工具中拆分、补建或重制。不能把候选模型页面上的预览图当作网站已经能达到的最终效果。

## 原型制作顺序

1. 固定一个首屏镜头，验证汉堡静态质感。
2. 完成完整 → 分层 → 合拢的可逆动画。
3. 接入一个技术方向的特写与真实资料菜单，验证观看和阅读的切换。
4. 加入合拢后拉远揭示圆桌的转场。
5. 扩展其他方向与院校数据，再检查手机和键盘操作。

第一阶段的成果应是可运行的模型与转场原型。现有交互草图只服务于讨论结构。
